# 追加: リリースバージョン

- プログラムバージョン: `V001.000.000`
- 画面表示: ロック解除画面の右下へ小さく表示
- 配布形式: フレームワーク依存EXE方式。`RELEASE/PassKinko_V001.000.000/パス金庫.exe` を起動する。
- 理由: 制限付きネットワーク/NuGet環境で `Microsoft.NET.ILLink.Tasks` を取得できず単一EXE発行が失敗するケースを避けるため。

# パス金庫 V001.000.000 プログラム仕様書

## 1. 目的

パス金庫は、Windows PCのローカル環境で資格情報を暗号化保存する小型デスクトップツールである。

管理項目は以下。

- サービス名
- ウェブサイト
- ユーザー名
- パスワード
- メモ
- 作成日
- 更新日

自動入力は行わない。ユーザーは検索、詳細確認、コピーにより利用する。

## 2. 保存場所

```text
%LOCALAPPDATA%\PassKinko\
  settings.json
  passkinko.db
```

配布ZIPにはローカルデータ、テストデータ、旧データを含めない。

## 3. 暗号化設計

- マスターパスワードからPBKDF2-HMAC-SHA256で鍵を導出する
- PBKDF2反復回数は600,000回
- KDF saltは公開パラメータとして`settings.json`に保存する
- KDF saltはポータブルバックアップにも含める
- 資格情報はAES-GCMで暗号化する
- AES-GCM Nonceは暗号化処理ごとにCSPRNGで新規生成する
- vault全体はマスターパスワード由来HMAC鍵で署名する
- マスターパスワードの単純ハッシュは保存しない
- 検証値は導出済みHMAC鍵による固定ペイロードHMACである

## 4. 運用状態の保護

失敗回数、ロックアウト期限など、マスターパスワード入力前に必要な運用状態はDPAPI CurrentUserで保護する。

ただし、DPAPIはPC/Windowsユーザーに依存するため、PC移行やOS再インストール時には復号できない。この場合は初期化しない。一定待機後、正しいマスターパスワードにより運用状態を復元先PCで再構築する。

待機時間はOS時刻変更の影響を受けにくいよう、アプリ起動中のモノトニック計測で扱う。

## 5. 旧データ・破損データへの対応

旧形式、破損、整合性不一致を検知した場合、アプリは起動自体を失敗させない。

画面上で以下を選べる。

- バックアップ復元
- 退避して新規開始
- 閉じる

「退避して新規開始」は既存ファイルを`quarantine_...`へコピー退避してから初回設定へ戻す。アプリは利用可能になるが、退避した旧データの復号は保証しない。

## 6. バックアップ/復元

V001.000.000のバックアップは`.pkbk`形式で、以下を含む。

- `settings.json`
- `passkinko.db`

バックアップ内の資格情報は平文ではなく、マスターパスワード由来鍵で暗号化された状態である。KDF saltも含むため、正しいマスターパスワードがあれば別PCでも復元できる。

DPAPI保護の運用状態はバックアップから除外または無効化し、復元先PCで再構築する。

## 7. CSV出力

CSVは平文の資格情報を含む。出力前にマスターパスワード再認証を行う。数式インジェクション対策として、表計算ソフトで数式扱いされやすい先頭文字はエスケープする。

CSVは移行・確認後、速やかに完全削除することをUI上で警告する。

## 8. ロック/保護

- 3分無操作でロック
- ユーザー名/パスワード表示は30秒後に伏字化
- クリップボードは30秒後に削除を試みる
- 複数起動は禁止
- トレイ復帰時は必ずロック解除画面へ戻す
- ロック時に詳細参照、一覧、入力欄、アクティブ鍵を明示クリアする

## 9. マスターパスワード更新

1年に1回の更新期限を持つ。更新処理は一時ファイル生成、検証、置換の順で行う。更新画面も自動ロック対象であり、再認証10回失敗時は鍵を破棄してロック解除画面へ戻る。

## 10. マスターパスワードを忘れた場合

既存データの復号はできない。これは暗号化ツールとして意図した仕様である。  
ただし、ツール自体は「退避して新規開始」で再利用できる。退避データは削除しない。

## 11. 既知の制約

- C# / WPFのstring特性上、メモリダンプ耐性には限界がある
- クリップボード履歴除外はOS環境に依存する
- 同一Windowsユーザー権限を完全に奪取された場合、画面操作やメモリ監視を完全には防げない


## 付録: リリースビルド

`build_release.bat` は、`PublishSingleFile` を使用しないフレームワーク依存EXE方式でリリース出力する。

これは、制限付きネットワーク環境で `Microsoft.NET.ILLink.Tasks` を取得できず単一EXE発行に失敗するケースを避けるためである。

出力先は以下。

```text
RELEASE\PassKinko_V001.000.000\パス金庫.exe
```

対象PCには .NET 8 Desktop Runtime が必要である。
